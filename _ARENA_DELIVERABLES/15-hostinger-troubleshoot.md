# عیب‌یابی: اپ دیپلوی شده ولی اجرا نمی‌شود

خطای فعلی: مرورگر و curl صفحه `This Page Does Not Exist` هاستینگر را برمی‌گردانند.

**معنی این خطا:** درخواست به وب‌سرور هاستینگر می‌رسد ولی **به اپ Node منتقل نمی‌شود**. اگر اپ اجرا می‌شد و فقط مسیر اشتباه بود، JSON می‌گرفتید نه HTML.

---

## 🔍 گام ۱ — کجا وضعیت اپ را ببینیم

طبق مستندات رسمی هاستینگر، داشبورد اپ Node.js در این مسیر است:

```
hPanel → Websites → [دامنه plum-newt-936322] → Dashboard
```

در آن صفحه دنبال این موارد بگردید:

| بخش | چه چیزی نشان می‌دهد |
|---|---|
| **وضعیت بالای صفحه** | باید بنویسد **Running** — اگر روی آن کلیک کنید دکمه **Restart** ظاهر می‌شود |
| **Last Deployment Details** | موفق بوده یا Failed + لینک لاگ کامل |
| **Deployments** | تاریخچه همه build ها |
| **Resource Usage** | نمودار CPU/RAM — اگر به خط قرمز رسیده، اپ kill شده |

> ⚠️ **نکته مهم از مستندات:** دکمه Restart فقط برای اپ‌های **server-side** ظاهر می‌شود.
> اگر آن را نمی‌بینید، یعنی هاستینگر اپ شما را **front-end استاتیک** تشخیص داده — که علت اصلی مشکل است.

---

## 🎯 گام ۲ — محتمل‌ترین علت

هاستینگر اپ‌ها را به دو دسته تقسیم می‌کند:

| نوع | مثال | رفتار |
|---|---|---|
| **Front-end استاتیک** | React, Vue, Angular, Vite | فقط فایل‌های build را سرو می‌کند — **هیچ سروری اجرا نمی‌شود** |
| **Back-end (server-side)** | Express, Next.js, NestJS, Fastify | یک پروسه دائمی اجرا می‌کند |

چون قبلاً framework روی `next` گیر کرده بود و ما یک پوشه `.next` ساختگی می‌ساختیم، **احتمال زیاد هاستینگر آن را استاتیک تشخیص داده** و فقط دنبال فایل HTML می‌گردد.

### چطور مطمئن شویم
در داشبورد، اگر **دکمه Restart نبود** → اپ استاتیک است → باید از نو ساخته شود.

## ✅ گام ۳ — راه‌حل: ساخت مجدد با تنظیم درست

### الف) اپ فعلی را حذف کنید
داشبورد اپ → Settings → Delete

### ب) اپ جدید بسازید
```
Websites → Add Website → Deploy Web App → Upload your website files
```

### ج) ZIP جدید را آپلود کنید
فایل `relay-hostinger.zip` (نسخه به‌روز — با bind روی `0.0.0.0`)

### د) تنظیمات build — این مرحله تعیین‌کننده است

| فیلد | مقدار | چرا |
|---|---|---|
| Framework | **Other** | ⛔ هرگز Next.js یا React |
| **Output directory** | **خالی بگذارید** | اگر پر باشد، اپ استاتیک تلقی می‌شود |
| **Entry file** | **`server.js`** | این چیزی است که پروسه را اجرا می‌کند |
| Build command | خالی یا `npm run build` | رله build لازم ندارد |
| Node version | ۲۰ یا ۲۲ | |

> 💡 **کلید ماجرا:** ترکیب «Output directory خالی + Entry file پر» به هاستینگر می‌گوید این یک اپ سرور است، نه سایت استاتیک.

### هـ) اگر گزینه Framework را نمی‌بینید
یعنی از مسیر «Front-End Application» رفته‌اید. برگردید و **Deploy Web App** را انتخاب کنید.

## 🔬 گام ۴ — تست بعد از ساخت

```bash
curl -i https://plum-newt-936322.hostingersite.com/health
```

| نتیجه | معنی |
|---|---|
| `{"ok":true,...}` | ✅ رله کار می‌کند |
| HTML صفحه ۴۰۴ هاستینگر | اپ هنوز استاتیک است یا اجرا نمی‌شود |
| `502 Bad Gateway` | اپ اجرا شده ولی کرش کرده — لاگ را ببینید |
| `403 Forbidden` | مشکل `.htaccess` — یک بار Redeploy کنید |

خروجی جدید `/health` حالا پورت و host را هم نشان می‌دهد:
```json
"listening": { "host": "0.0.0.0", "port": 3000 }
```

## 📁 گام ۵ — بررسی فایل‌ها روی سرور

طبق مستندات، فایل‌های اپ‌های back-end **بیرون از `public_html`** ذخیره می‌شوند:

```
/home/{username}/domains/{domain}/nodejs        ← فایل‌های اپ
/home/{username}/domains/{domain}/public_html/.htaccess   ← مسیریابی
```

در **File Manager** این دو را چک کنید:

1. آیا `server.js` در پوشه `nodejs` هست؟
2. آیا `.htaccess` در `public_html` وجود دارد؟

اگر `.htaccess` نبود → یک بار **Redeploy** کنید تا خودکار ساخته شود.
اگر `server.js` در `nodejs` نبود → آپلود ناقص بوده.

## 🛟 گام ۶ — اگر هیچ‌کدام جواب نداد

دو گزینه داریم:

### گزینه الف) نسخه PHP رله
پلن Business شما PHP دارد و PHP **بدون هیچ تنظیمی** کار می‌کند — فقط یک فایل در `public_html` می‌گذارید و بلافاصله فعال است.

| | Node.js | PHP |
|---|---|---|
| راه‌اندازی | تنظیم framework، port، entry file | فقط آپلود فایل |
| احتمال موفقیت | متوسط | **بسیار بالا** |
| قابلیت‌ها | همه | **دقیقاً همه** |

رله فقط یک عبوردهنده HTTP است — PHP این کار را به همان خوبی انجام می‌دهد.

### گزینه ب) تیکت به پشتیبانی هاستینگر
متن پیشنهادی:

> سلام. یک اپ Node.js ساده (بدون هیچ dependency) روی پلن Business آپلود کرده‌ام.
> فایل اصلی `server.js` است و روی `0.0.0.0` و متغیر `PORT` گوش می‌دهد.
> اپ به‌عنوان Framework=Other و Entry file=server.js تنظیم شده و Output directory خالی است.
> ولی دامنه صفحه «This Page Does Not Exist» را برمی‌گرداند و درخواست به اپ نمی‌رسد.
> لطفاً بررسی کنید آیا پروسه Node اجرا می‌شود و لاگ آن را برایم بفرستید.

## 📋 اطلاعاتی که برای کمک بیشتر لازم دارم

3. آیا در File Manager پوشه `domains/{domain}/nodejs` وجود دارد و `server.js` داخلش هست؟
4. اسکرین‌شات صفحه Dashboard اپ

# سند ۲ — معماری فنی: شروع کم‌هزینه با cPanel، رشد تدریجی به VPS

## ۲٫۰ تصمیم اصلاح‌شده: «اول cPanel، بعد VPS»

شما درست می‌گویید — **شروع با VPS در ماه اول، هزینه و پیچیدگی بی‌دلیل است.** معماری را طوری طراحی می‌کنیم که:

> با هاست اشتراکی cPanel (هاستینگر + میزبان‌فا) شروع کنیم، و **بدون بازنویسی کد**، هر وقت نیاز شد به VPS مهاجرت کنیم.

این اصل، نام فنی دارد: **Infrastructure-Agnostic Design** (معماری مستقل از زیرساخت). یعنی از روز اول طوری کد می‌نویسیم که جابه‌جایی زیرساخت فقط تغییر متغیر محیطی باشد، نه بازنویسی.

### چرا این تصمیم درست است؟
| دلیل | توضیح |
|---|---|
| هزینه | cPanel اشتراکی ماهی ~۲۰۰-۵۰۰ هزار تومان در برابر VPS ~۱٫۵-۳ میلیون |
| سرعت شروع | امروز سفارش می‌دهید، امشب سایت بالاست — VPS چند روز راه‌اندازی می‌خواهد |
| بدون DevOps | نیازی به مدیریت Docker، امنیت سرور، بکاپ دستی، آپدیت سیستم‌عامل نیست |
| اثبات مدل | اول ثابت کنید محصول می‌فروشد، بعد روی زیرساخت خرج کنید |
| ریسک کم | اگر مدل کار نکرد، ضرر مالی ناچیز است |

### تجربه‌ای که از قبل دارید ✅
پروژه `ehsansalehi.ir` **همین الان روی cPanel میزبان‌فا در حال اجراست** — با Next.js standalone، MySQL، انتشار خودکار در ۸ شبکه اجتماعی، و cron ساعتی. یعنی این مسیر برای شما **آزموده‌شده** است، نه یک آزمایش جدید. حتی مشکلات شناخته‌شده‌اش (مثل `HOSTNAME` در standalone) را حل کرده‌اید و در `docs/mizbanfa-fast-deploy.md` مستند است.

## ۲٫۱ معماری سه مرحله‌ای (Phase-Gated Infrastructure)

```
مرحله ۱ (ماه ۱-۳)        مرحله ۲ (ماه ۴-۶)         مرحله ۳ (ماه ۷+)
   💚 ارزان                  💛 هیبرید                 🧡 مقیاس‌پذیر
┌──────────────┐        ┌──────────────┐        ┌──────────────┐
│  cPanel      │        │  cPanel      │        │  VPS اصلی    │
│  هاستینگر    │   →    │  (سایت)      │   →    │  (همه‌چیز)   │
│  + میزبان‌فا  │        │  +           │        │  +           │
│              │        │  VPS کوچک    │        │  cPanel ایران│
│  همه‌چیز     │        │  (AI/ویدئو)  │        │  (آینه بحران)│
└──────────────┘        └──────────────┘        └──────────────┘
 ~۵۰۰ هزار/ماه          ~۱٫۵ میلیون/ماه          ~۳-۵ میلیون/ماه
```

**محرک ارتقا (Trigger)** — دقیقاً کِی باید به مرحله بعد بروید:

| از مرحله | به مرحله | محرک |
|---|---|---|
| ۱ → ۲ | هیبرید | یکی از این‌ها: بیش از ۳۰۰ محصول، یا نیاز به رندر ویدئو خودکار، یا CPU هاست مدام محدود می‌شود، یا بیش از ۱۵۰ سفارش در ماه |
| ۲ → ۳ | VPS کامل | بیش از ۸۰۰ محصول، یا بیش از ۵۰۰ سفارش ماهانه، یا نیاز به پرو آنلاین سطح ۳ |

> **قانون طلایی:** تا وقتی محرک فعال نشده، پول خرج زیرساخت نکنید. آن پول را خرج تبلیغات و کالا کنید.

## ۲٫۲ مرحله ۱ — همه‌چیز روی cPanel (ماه ۱ تا ۳)

### تقسیم کار بین دو هاست

| نقش | هاست | چرا |
|---|---|---|
| **سایت اصلی فروشگاه + دیتابیس + پنل** | **میزبان‌فا (ایران)** | دامنه `.ir`، اینماد، درگاه پرداخت، سرعت برای کاربر ایرانی، در دسترس بودن در قطعی اینترنت |
| **موتور اتوماسیون + AI + انتشار شبکه‌های اجتماعی** | **هاستینگر (خارج)** | دسترسی به AgentRouter، اینستاگرام، تلگرام، پینترست و یوتیوب که از IP ایران مسدودند |

این تقسیم‌بندی **دقیقاً منطق درست** است: هر کار روی هاستی که برایش مناسب است.

```
        کاربر ایرانی
             │
    ┌────────▼─────────────────────────┐
    │  میزبان‌فا cPanel (shop.ir)       │
    │  ─────────────────────────────    │
    │  • Next.js (فروشگاه، پنل، API)   │
    │  • MySQL (محصول، سفارش، مشتری)   │
    │  • تصاویر محصول (public/)        │
    │  • درگاه پرداخت + پیامک          │
    │  • پرو آنلاین سطح ۱ و ۲          │
    │    (کاملاً سمت-کاربر، رایگان)     │
    │  • Cron هر ۵ دقیقه               │
    └────────┬─────────────────────────┘
             │  API امن با CRON_SECRET
             │  (همان الگوی فعلی شما)
    ┌────────▼─────────────────────────┐
    │  هاستینگر cPanel (engine.com)     │
    │  ─────────────────────────────    │
    │  • فراخوانی AgentRouter          │
    │  • تولید متن، کپشن، مقاله        │
    │  • انتشار در ۱۰ شبکه اجتماعی     │
    │  • Vision (تشخیص محصول از عکس)   │
    │  • Cron ساعتی محتوا              │
    └───────────────────────────────────┘
             │
    شبکه‌های اجتماعی + AgentRouter
```

### چه چیزی روی cPanel کار می‌کند و چه چیزی نه؟

| قابلیت | روی cPanel؟ | یادداشت |
|---|---|---|
| Next.js فروشگاه | ✅ بله | با Node.js App در cPanel — تجربه‌اش را دارید |
| MySQL | ✅ بله | استاندارد cPanel |
| پردازش تصویر (حذف پس‌زمینه، برش، واترمارک) | ✅ بله با احتیاط | Sharp/Jimp روی cPanel کار می‌کند؛ برای عکس‌های سنگین کمی کند |
| فراخوانی AgentRouter | ✅ بله (روی هاستینگر) | فقط HTTP request است |
| انتشار شبکه‌های اجتماعی | ✅ بله | کد فعلی شما همین حالا این کار را می‌کند |
| Cron | ✅ بله | cPanel Cron Jobs — تجربه‌اش را دارید |
| پرو آنلاین سطح ۱ و ۲ | ✅ بله | سمت-کاربر (مرورگر)، بار سروری ندارد |
| Redis / صف حرفه‌ای | ⚠️ معمولاً نه | **جایگزین:** صف مبتنی بر جدول MySQL + Cron هر ۵ دقیقه |
| n8n | ❌ نه | **جایگزین:** سناریوها به‌صورت کد در همان Next.js + Cron |
| رندر ویدئو با FFmpeg | ❌ معمولاً نه | **جایگزین‌ها در بخش ۲٫۴** |
| MinIO | ❌ نه | **جایگزین:** فضای دیسک هاست + CDN |
| MeiliSearch | ❌ نه | **جایگزین:** MySQL FULLTEXT (برای زیر ۱٬۰۰۰ محصول کافی است) |
| پرو آنلاین سطح ۳ (AI) | ❌ نه | فاز VPS |

### جایگزین‌های هوشمند (Graceful Degradation)

این مهم‌ترین بخش معماری است — هر قابلیتی که روی cPanel نیست، یک **جایگزین کارآمد** دارد:

| قابلیت اصلی | جایگزین cPanel | افت کیفیت |
|---|---|---|
| Redis + BullMQ | جدول `job_queue` در MySQL + Cron ۵ دقیقه‌ای | تأخیر ۵ دقیقه به‌جای آنی — قابل قبول |
| n8n | ماژول `lib/workflows/` با همان منطق در TypeScript | نیاز به دیپلوی برای تغییر سناریو |
| MinIO | `public/uploads/` + CDN ابرآروان جلوی آن | مدیریت دستی فضا |
| MeiliSearch | MySQL FULLTEXT + ایندکس فارسی | جستجوی ضعیف‌تر در غلط املایی |
| FFmpeg | سرویس ابری رایگان/ارزان (بخش ۲٫۴) | هزینه کم به ازای هر ویدئو |
| Docker | Node.js App مستقیم در cPanel | بدون ایزولاسیون |

**همه این جایگزین‌ها پشت یک interface یکسان قرار می‌گیرند** (مثلاً `lib/queue/index.ts`)، پس وقتی به VPS رفتید فقط پیاده‌سازی عوض می‌شود، نه کدی که از آن استفاده می‌کند.

### پلن هاست پیشنهادی مرحله ۱

| مورد | مشخصات پیشنهادی |
|---|---|
| میزبان‌فا | هاست ووکامرس/Node ایران، حداقل ۵GB فضا، NVMe، پشتیبانی Node.js 20+ |

- امکان اجرای Cron Job با فاصله ۵ دقیقه
- دسترسی SSH (برای دیپلوی سریع)
- محدودیت CPU/RAM چقدر است (برای پردازش تصویر مهم است)

## ۲٫۳ مرحله ۲ — هیبرید (ماه ۴ تا ۶)

وقتی محرک فعال شد، یک VPS کوچک (Hostinger KVM 1 یا KVM 2) فقط برای **کارهای سنگین** اضافه می‌شود:
- رندر ویدئو با FFmpeg
- پردازش تصویر انبوه
- n8n برای سناریوهای پیچیده
- Redis برای صف واقعی

سایت و دیتابیس **همچنان روی cPanel** می‌مانند. VPS فقط یک «کارگر» است که با API فراخوانی می‌شود.

مزیت: هزینه فقط ~۹ دلار در ماه اضافه می‌شود ولی همه محدودیت‌های سنگین برطرف می‌شود.

## ۲٫۴ راه‌حل ویدئو در فاز cPanel

چون FFmpeg روی هاست اشتراکی معمولاً در دسترس نیست، سه گزینه داریم:

| گزینه | هزینه | کیفیت | توصیه |
|---|---|---|---|
| **الف) ویدئو در مرورگر** — رندر با Canvas + WebCodecs سمت کاربر (در پنل ادمین) | رایگان | خوب | ✅ فاز ۱ |
| **ب) سرویس ابری رندر** | ~۵-۲۰ سنت هر ویدئو | عالی | ✅ فاز ۱-۲ |
| **ج) VPS کوچک اختصاصی رندر** | ~۶ دلار/ماه | عالی و نامحدود | ✅ فاز ۲ |
| د) ویدئو دستی با اپ موبایل | رایگان | متغیر | فقط اضطراری |

**پیشنهاد:** فاز ۱ با گزینه الف شروع کنید (ادمین یک بار در روز پنل را باز می‌کند و ویدئوها رندر می‌شوند)، و به محض رسیدن به مرحله ۲، گزینه ج.

**جایگزین ساده‌تر و بسیار مؤثر:** به‌جای ویدئو، **کاروسل عکس متحرک** (اسلایدشو GIF/WebP) بسازید که با Sharp روی همان cPanel قابل تولید است. برای اینستاگرام و تلگرام تقریباً همان تأثیر را دارد.

## ۲٫۵ مرحله ۳ — VPS کامل (ماه ۷+)

وقتی کسب‌وکار اثبات شد و درآمد ماهانه بالای ~۵۰۰ میلیون تومان است:

قیمت VPS هاستینگر حدود ۶٫۵ تا ۲۶ دلار در ماه است و KVM 2 برای بارهای کاری اتوماسیون کافی است ([مرجع](https://ivristech.com/n8n-self-hosting-hostinger/), [مرجع](https://hostadvice.com/hosting-company/hostinger-reviews/n8n-hosting-review/)).

مستندات AgentRouter تأکید می‌کند Base URL حالت Claude Code **نباید** `/v1` داشته باشد و نباید با حالت OpenAI-compatible قاطی شود.

**خبر خوب:** پروژه فعلی شما همین الان `OPENAI_BASE_URL` و `OPENAI_MODEL` را می‌خواند — اتصال به AgentRouter بدون تغییر کد ممکن است.

**⚠️ نکته مهم:** AgentRouter برای **متن و کدنویسی** است. برای تولید/ویرایش تصویر و ویدئو به سرویس جداگانه نیاز داریم.

**لایه انتزاع اجباری:** ماژول `lib/ai/provider.ts` که همه فراخوانی‌های AI از آن رد شود، با: انتخاب مدل بر اساس نوع کار، Fallback خودکار، کش پاسخ‌های تکراری (کاهش هزینه تا ۴۰٪)، سقف مصرف روزانه و لاگ هزینه.

## ۲٫۹ امنیت

- HTTPS اجباری + هدرهای امنیتی + WAF ابرآروان
- SSH با کلید، محدودسازی دسترسی cPanel
- هیچ کلیدی در گیت — فقط `.env` روی سرور
- نقش‌های کاربری `owner/admin/seller/support/viewer` با RBAC
- رمزنگاری توکن‌های شبکه‌های اجتماعی در دیتابیس (AES-256)
- Rate limit روی API عمومی و لاگین
- لاگ حسابرسی برای هر تغییر قیمت، موجودی و انتشار
- **حریم خصوصی کودک** (سند ۱۱): عکس کودک هرگز ذخیره نشود
- بکاپ ۳-۲-۱: روزانه cPanel، شبانه دانلود خودکار، هفتگی فضای ابری؛ تست بازیابی ماهانه

## ۲٫۱۰ عملکرد

هدف: **LCP زیر ۲٫۵ ثانیه روی موبایل ایرانی**.
- ISR برای صفحات محصول و دسته
- تصاویر WebP/AVIF، سه سایز، کش CDN طولانی
- فونت فارسی محلی با `font-display: swap`
- JS اولیه زیر ۱۵۰KB؛ کامپوننت پرو آنلاین با dynamic import (فقط وقتی کلیک شد بارگذاری شود)

## ۲٫۱۱ برنامه تداوم کسب‌وکار (قطعی اینترنت)

مزیت بزرگ معماری cPanel-اول: **سایت اصلی از روز اول روی هاست ایران است**، پس در قطعی اینترنت بین‌الملل، فروشگاه شما زنده می‌ماند.

| سطح | وضعیت | رفتار سیستم |
|---|---|---|
| 🟢 سبز | عادی | همه‌چیز فعال |
| 🟡 زرد | کندی بین‌الملل | سایت و فروش کامل کار می‌کند؛ فقط انتشار اینستاگرام/پینترست به تأخیر می‌افتد و در صف می‌ماند |
| 🔴 قرمز | قطع کامل بین‌الملل | سایت، پرداخت، پیامک، بله/ایتا/روبیکا فعال؛ AI و شبکه‌های خارجی متوقف؛ محتوای از پیش تولیدشده از بافر منتشر می‌شود |

**بافر محتوا:** همیشه ۷ روز محتوای آماده در صف نگه دارید تا در قطعی، کانال‌های داخلی خالی نمانند.

هاست‌های ایرانی در دوره‌های محدودیت شدید اینترنت به‌مراتب در دسترس‌تر بوده‌اند ([مرجع](https://mizbanfa.net/)).
